# 🤝 Contributing

Thanks for helping maintain the tap. This guide covers the repository layout,
local checks and the automation that keeps the casks current.

## Ways to contribute

- **Cask or tap problems** — open an
  [issue](https://github.com/setchy/homebrew-brews/issues) or send a PR.
- **Bugs in an app** — report them upstream in the app's repository (for
  Atlassify: [setchy/atlassify](https://github.com/setchy/atlassify/issues)).
  They can't be fixed in this tap.
- **Version bumps** — [Renovate](https://docs.renovatebot.com/) opens these
  automatically, so manual version-only PRs aren't needed.

## Repository layout

- `Casks/` — one cask per file, named after the cask token, e.g.
  `Casks/atlassify.rb`.
- `renovate.json` — Renovate managers and package rules for this tap.
- `.github/workflows/cask-lint.yml` — `brew style` + `brew audit` on cask
  changes, plus a weekly online audit.
- `.github/workflows/renovate.yml` — validates the Renovate config.
- `.github/zizmor.yml` — workflow security policy, checked with
  [zizmor](https://github.com/zizmorcore/zizmor).
- `.github/workflows/actions.lock` — resolved action refs generated by
  `gh actions-lock`; update it with that command instead of editing it by hand.

## Adding or changing a cask

1. Add or edit `Casks/<token>.rb`. The filename must match the cask token.
2. Check it locally:

   ```sh
   brew style Casks/<token>.rb
   HOMEBREW_DEVELOPER=1 brew install --cask ./Casks/<token>.rb
   ```

   Homebrew 7 no longer loads casks from file paths by default: `brew install`
   needs `HOMEBREW_DEVELOPER=1`, and `brew audit` rejects paths outright. To
   audit locally, tap the repo, trust the cask, and use the tap-qualified name:

   ```sh
   brew tap setchy/brews
   brew trust --cask setchy/brews/<token>
   brew audit --cask setchy/brews/<token>
   ```

   [Cask lint](https://github.com/setchy/homebrew-brews/actions/workflows/cask-lint.yml)
   runs the same style and audit checks on every PR, plus a weekly
   `--online --arch=all` audit.
3. Open a PR. CODEOWNERS routes it to [@setchy](https://github.com/setchy).

### Cask conventions

- If the app ships its own updater, use `sha256 :no_check` plus
  `auto_updates true` (as `atlassify` does). Otherwise pin the checksum; the
  Renovate config here only bumps `version`, so a pinned cask needs its
  checksums updated in the same PR.
- Use Homebrew's `arch` and `os` substitutions when upstream publishes
  architecture- or OS-specific assets. For example:

  ```ruby
  arch arm: "-arm64"
  os macos: "-mac.zip", linux: ".AppImage"

  url "https://github.com/setchy/atlassify/releases/download/v#{version}/Atlassify-#{version}#{arch}#{os}"
  ```

- Set `depends_on macos:` to the artifact's real minimum
  (`LSMinimumSystemVersion` in `Contents/Info.plist`), not the vendor's
  marketing page.
- Keep cask stanzas in Homebrew's expected order and run `brew style` before
  pushing; the CI check is not auto-fixing.

## Automation

- **Renovate** watches `setchy/atlassify` GitHub tags through a custom regex
  manager that matches the `version` stanza in `Casks/atlassify.rb`. It opens a
  PR and automerges it. To add another cask, add a matching custom manager
  entry in `renovate.json`.
- **Cask lint** runs `brew style` + `brew audit` on changes to `Casks/**` and
  weekly against `main`. The weekly run also audits all architectures online,
  so dead URLs and expired checksums surface even when nothing changed.
- **Renovate config validation** runs on changes to `renovate.json` or the
  workflow.
- **zizmor** vets workflow dependencies; action refs are tracked in
  `.github/workflows/actions.lock`.

## Commit and PR titles

Use [Conventional Commits](https://www.conventionalcommits.org/) so the history
and Renovate PRs stay consistent:

- `fix(atlassify): ...`
- `chore(deps): update dependency setchy/atlassify to vX.Y.Z`
- `docs: ...`

Keep a PR focused on one change where possible.
